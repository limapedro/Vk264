# Parity source layout (x264 mirror)

The byte-exact parity code used to live in a single 6,700-line `dct_parity.cpp`.
It is now split into small, domain-oriented modules under
`Vk264/src/parity/`, each mirroring the x264 source file(s) whose behaviour
it checks. This makes it practical to find the reference and the fixture for
any given syntax element without scrolling through unrelated motion, CABAC and
bitstream code.

## Why textual inclusion

The extracted x264 reference is generated by `extract_reference.py` into
`upstream_*.inc` files. Those files contain `static` functions and
namespace-scope `const` tables, and several define external-linkage functions
(`x264_cabac_init`, `x264_iter_kludge`, ...). The `parity/*.inc` modules are
therefore **textually included into one translation unit** by the 24-line
`dct_parity.cpp` master (both in `Vk264/src/`). This keeps upstream semantics byte-for-byte identical
while giving the source a modular, reviewable layout. Splitting into independent
translation units would require changing the extractor and is deliberately out
of scope.

Reconstruction proof: concatenating the module bodies reproduces the original
`dct_parity.cpp` **byte for byte** (355,633 bytes). Reproduce it with
`python harness/check_parity_layout.py --base 1c6c50b`. The full suite (52/52)
plus the 4 automated parity gates pass unchanged.

## Module map

| Module | Mirrors (x264) | Contains |
|---|---|---|
| `x264_reference.inc` | `common/*`, `encoder/*` | extracted `.inc` files, reduced `x264_t`, shared types/macros, Vulkan `execute()` harness, `matchesNativeBytes` |
| `fixtures_transform.inc` | `common/dct.c`, `common/quant.c` | `verify` (DCT sizes), `verifyQuant`, `verifyDc`, `verifyZigzag`, `verifyChromaDc`, `verifyCoeffAnalysis`, `verifyChromaOptimize` |
| `fixtures_intra.inc` | `common/predict.c`, `encoder/analyse.c` | `verifyPredictIntra`, `verifyI4x4Decision`, `encodeI4x4Frame`, `verifyPredictDirectional` |
| `fixtures_deblock.inc` | `common/deblock.c` | `verifyDeblockFilter`, `verifyDeblockStrength`, `verifyDeblockFrame` |
| `fixtures_cabac.inc` | `encoder/cabac.c` | `cabacCorpus`, `verifyCabac`, `verifyCabacRefIdx` |
| `fixtures_cavlc.inc` | `encoder/cavlc.c` | `cavlcResidualCorpus`, `verifyCavlcResidual` |
| `fixtures_motion.inc` | `common/mc.c`, `common/me.c`, `common/mvpred.c` | `verifyMvPrediction`, `verifyMotionCompensation`, `verifyMotion*`, `verifyMotionBidir` |
| `fixtures_syntax.inc` | `common/bitstream.c`, `encoder/set.c`, `encoder/encoder.c` | `verifyBitstream`, `verifyNal`, `verifyParameters`, `verifySliceHeader` |
| `fixtures_macroblock.inc` | `encoder/macroblock.c` | `verifyLuma4x4`, `verifyInter8x8`, `verifyIntraChroma` |
| `resident_cavlc.inc` | resident pipeline | raw-clip readers, motion input packing, `encodeResidentCavlcFrame` |
| `resident_cabac.inc` | resident pipeline | `cabacEncodeBins`, `packAnnexB`, `encodeResidentCabacFrame` |
| `resident_pipeline.inc` | resident pipeline | B-frame config, `encodeCabacClip`, public `x264_vulkan::encode` |
| `fixtures_aq.inc` | `encoder/ratecontrol.c` | `verifyAqVariance` |
| `dispatch.inc` | — | `runParityTests` — the name → `verify*` mapping |

The shader side is already split the same way: `Vk264/vulkan/*.comp` and
`*.glsl` mirror the x264 C modules (for example `cabac.comp` mirrors
`encoder/cabac.c`, `cavlc_residual.glsl` mirrors `encoder/cavlc.c`,
`inter_frame.comp` mirrors `common/me.c`).

## Finding a fixture from a CTest name

1. `Vk264/vulkan/CMakeLists.txt` registers `dct_parity <test name> <spv>`. It
   builds the fixtures from `Vk264/src/`; `Vk264/vulkan/` itself holds shaders only.
2. `parity/dispatch.inc` maps that name to a `verify*` function.
3. Use the table above to find the module with that function, and the x264
   source it mirrors.

## Adding a fixture (bottom-up standard)

1. Add the `verifyXxx()` function to the matching module in `parity/`. If it
   needs a new x264 function, add it to `extract_reference.py` so it is
   extracted verbatim, then `#include` the generated `.inc` in
   `parity/x264_reference.inc` in the same relative position as upstream.
2. Add the name → function mapping in `parity/dispatch.inc`.
3. Register the CTest in `Vk264/vulkan/CMakeLists.txt`. Add a byte-exact
   parity gate there too if the case must stay exact.
4. Prove it: `ctest --test-dir build -C Release --output-on-failure` and, for
   exact cases, `python harness/parity_check.py ...` → `BYTE-EXACT MATCH`.

No logic should change in a layout-only PR: the byte reconstruction check
above is the regression guard.
