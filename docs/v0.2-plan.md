# Vk264 v0.2 quality and GPU budgets

The main target is x264 quality at the same preset, resolution, frame rate,
and achieved video bitrate. Start with 1080p60 near 6 Mbps and retain the
Vulkan shader path. Compare the same source frames, report actual bitrate
and encode throughput, and include crops at the frames where block artifacts
are visible. Track VMAF, luma and chroma error, 16-pixel seam error, and p95
frame time. Keep the restricted x264 control alongside full x264 so tool
differences are visible in the results.

## Locate the first bad prediction

- Use Warzone frame 31 as the first regression case and use Fortnite for
  validation. Trace the affected macroblocks through reference choice, motion
  vector, prediction, quantized residual, and pre- and post-filter reconstruction.
- Replay the same blocks with the recorded prediction plus the full residual,
  and with alternate predictions at the same quantizer. Measure how much error
  comes from the chosen prediction, coefficient quantization, and coding decisions.
- Run full clips at a matched achieved bitrate after each promising change.
  Compare finer motion partitions and intra candidates with the current
  16×16 path. Use the measured bit cost to evaluate whether candidates earn
  their place before expanding entropy coding or rewriting the pipeline.

## Calibrate preset tiers

Use roughly 5%, 10%, 20%, 30%, 40%, and 50% as the initial GPU-time budgets.
On the GTX 1660 SUPER at 60 fps, those are approximately 0.83, 1.67, 3.33,
5.00, 6.67, and 8.33 milliseconds of Vk264 GPU work per frame. Measure GPU
time with Vulkan timestamps and separately record OBS encoding lag while
gameplay competes for the GPU. Report the GPU, input, and resolution with each
result. Select the highest measured quality within each tier and keep the
1080p60 delivery deadline visible when deciding the final preset names.
